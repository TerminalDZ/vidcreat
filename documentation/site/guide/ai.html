AI integration ​

ReelForge works on its own: you write the script, design scenes in the editor and render. If you use an AI assistant, it can do the heavy lifting: write the script, build every scene, look at rendered frames and fix problems. You stay in control. You record your own voice, check the cues by ear and approve the result in the editor.

The render engine contains no AI: it draws every frame deterministically from episode.yaml. Two optional helpers run on your computer:

  • Speech alignment (align_cues, reelforge align) marks every line and word from voice.wav. It works from pause detection alone; reelforge align --setup downloads the optional speech models (Whisper and Silero VAD) once, and after that alignment runs offline.
  • Scene suggestions (suggest_scene, suggest_scenes) use a built-in keyword dictionary, or a language model you configure (see Local and cloud models).

Three ways in ​

All three serve the same tools from one registry, so names, arguments and results are identical (ADR-014). The MCP tools reference lists every tool.

TransportStart itEndpointUse it for
MCP over stdioyour client runs reelforge mcpstandard input/outputClaude Code, Cursor, VS Code, Codex, Gemini CLI
MCP Streamable HTTPreelforge studio (keep it running)http://127.0.0.1:4310/mcpclients that prefer a URL, several clients
REST and OpenAPIreelforge studiohttp://127.0.0.1:4310/api/v1agent frameworks with function calling
bash
./reelforge mcp          # macOS / Linux
reelforge.cmd mcp        # Windows

You don't run the stdio server yourself: your client starts it when needed. It runs on your computer and never sends your files anywhere; the AI service only sees what your client sends it.

The REST API answers GET /api/v1/tools (add ?format=openai for OpenAI function definitions), POST /api/v1/tools/<name> with the arguments as JSON, and GET /api/v1/openapi.json for GPT Actions and other OpenAPI importers. The dashboard also serves /.well-known/mcp.json (a server card) and /llms.txt / /llms-full.txt (the documentation in one file).

Client setup ​

The project folder already contains configuration for Claude Code (.mcp.json), Cursor (.cursor/mcp.json), VS Code (.vscode/mcp.json) and Gemini CLI (.gemini/settings.json). Open the folder in the client and approve the reelforge server. For example, with Claude Code:

bash
claude mcp add reelforge -- node packages/cli/bin/reelforge.js mcp

Try: "Make a 40-second English episode about database indexes, preview it and fix any issues."

Every other client (Claude Desktop, Windsurf, Codex CLI, Zed, Continue, LM Studio and any OpenAI-compatible framework), in stdio and HTTP variants, is in AI client setup. The dashboard's Connect AI page (/connect) shows the same snippets with your real paths and a connection test.

Toolsets ​

Small context windows work better with fewer tools. Ask for one or more toolsets:

bash
reelforge mcp --toolsets basic,design

Over HTTP use /mcp?toolsets=basic (also on /api/v1/tools and /api/v1/openapi.json).

ToolsetContains
basicread, create (from a script or a template), add scenes, validate, preview, cues
designstructured edits, full YAML, component schemas, blueprints and scene suggestions
renderrender, status, cancel, open the editor, environment check
allevery tool (the default)

Tool tiers ​

Pick the tools that match the model's strength. Every write tool returns the validation summary, one fix hint per problem (fixes) and the recommended next step (next), so any model can correct itself in a loop.

TierForToolsThe model writes
1small modelslist_templates → create_from_template, suggest_scenesa flat object of slot values; no YAML
2medium modelscreate_episode, list_blueprints → add_scenethe script and a few fields per scene
3strong modelsedit_episode, write_episode_yaml, get_component_schemaany element, prop, time and animation

Shared tools for every tier: get_episode, validate_episode, preview_frames (images for vision models plus a text layout description for text-only models), draft_cues, align_cues, set_cues, render_episode, get_render_status, cancel_render, open_editor, doctor and get_guide.

Local and cloud models ​

ReelForge's own scene suggestions can use a language model. Nothing is configured by default; without a model, suggestions come from the keyword dictionary. Set environment variables, or write llm.json in the ReelForge config folder (%APPDATA%\reelforge, ~/Library/Application Support/reelforge or ~/.config/reelforge) with the same keys (provider, baseUrl, model, apiKey).

VariableMeaning
REELFORGE_LLM_PROVIDERopenai (any OpenAI-compatible server), anthropic or ollama
REELFORGE_LLM_BASE_URLServer URL; the provider is guessed from it when not set
REELFORGE_LLM_MODELModel name
REELFORGE_LLM_API_KEYAPI key for cloud services (stored only in your environment or file)
bash
# Local model through Ollama (default address 127.0.0.1:11434)
REELFORGE_LLM_PROVIDER=ollama REELFORGE_LLM_MODEL=qwen2.5:1.5b reelforge studio

# LM Studio, llama.cpp server, vLLM or any OpenAI-compatible endpoint
REELFORGE_LLM_BASE_URL=http://127.0.0.1:1234/v1 REELFORGE_LLM_MODEL=my-model reelforge studio

# A cloud API
REELFORGE_LLM_PROVIDER=anthropic REELFORGE_LLM_API_KEY=... reelforge studio

On Windows PowerShell set variables with $env:REELFORGE_LLM_MODEL = "qwen2.5:1.5b" before the command. Answers are constrained to the component schemas (JSON Schema output where the server supports it, a grammar on Ollama, otherwise a validate-and-repair loop). The dashboard shows which model is in use.

Evaluating models ​

scripts/eval-agents.mjs runs one authoring task per industry against a model through the real tool registry and scores each produced episode: created, valid, no overlaps, inside the safe zones, right language, every line covered (and, with --render, renders).

bash
pnpm build
node scripts/eval-agents.mjs --mock                                   # scripted model, offline (CI)
node scripts/eval-agents.mjs --base-url http://127.0.0.1:11434/v1 --model qwen2.5:7b
node scripts/eval-agents.mjs --base-url https://api.example.com/v1 --model my-model --api-key "$KEY" \
  --toolsets basic --tasks healthcare,finance --out results.md

The endpoint must speak OpenAI-compatible Chat Completions with tool calling. Publish results with this table (the script writes it with --out):

Security ​

  • The dashboard and editor bind to 127.0.0.1. Every request must carry a loopback Host (or a name in REELFORGE_ALLOWED_HOSTS), which blocks DNS rebinding; no CORS headers are sent and writes are JSON-only.
  • reelforge studio --host <address> (or REELFORGE_HOST) binds elsewhere. Then /mcp and /api/v1 require Authorization: Bearer <token>, and other computers can reach only the AI endpoints, never the dashboard UI. REELFORGE_REQUIRE_TOKEN=1 requires the token on loopback too.
  • The token is created on first use and stored in the config folder (token, readable only by you where the system supports it). The Connect AI page shows it only to a browser on the same computer.
  • Plain HTTP carries the token in clear text: on an untrusted network, put the dashboard behind a TLS proxy.
  • Tools only read and write inside the project folder; renders are served only from out/.

Tips ​

  • Ask the assistant to look. Say "preview the frames and fix anything that looks off". The assistant receives the frames as images.
  • Keep the voice human. ReelForge never generates voices. Record yourself, let align_cues mark the lines and words, then listen through once in the editor's Cues mode and fix any line by ear.
  • Review in the editor. Ask for open_editor to get a link. Everything the assistant wrote is editable visually, and every change can be undone.
  • Large changes: the assistant can rewrite the whole episode.yaml. The file is checked before it is saved, and invalid YAML is refused.
